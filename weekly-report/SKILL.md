# 每周周报制作 Skill（weekly-report）

## Overview

把"每周做周报"从手工流程固化为自动化流程。输入**上一周已完成的周报 PPT** + **本周新增素材文件**，输出**新一周完整 PPT**（约 30 页，含计划组、科研组、质量组、运维组四部分），全程保持团队既有格式、字体、图表、版式不变。

所有格式细节、映射关系、操作规范都沉淀在三份参考文档中，执行前必须先阅读：

| 文档 | 内容 |
|---|---|
| `references/ppt_structure.md` | 30 页 PPT 完整版式：每页标题、表格结构、图表位置、关键形状定位（TextBox 42 / 矩形 9 / 椭圆 8/13/20 / 表格 1/4/10/11/17/26 / 图表 2）、页面复制规则 |
| `references/excel_mapping.md` | 各输入文件 → PPT 页的映射：项目表 12 列映射、中心分组映射（8 中心）、资金/物资列映射、台账汇总统计、科研组 doc 三要素结构 |
| `references/format_rules.md` | 三条铁律、字体体系、编号/日期规则、表格操作规范、仪表盘统计口径、交付检查清单 |

## 触发条件

用户表达以下任一意图即触发本 Skill：

- "做周报 / 更新周报 / 生成新一周周报"
- "WK35 周报"、"本周周报"、"下周一交的周报"
- 提供了上周周报 PPT + 本周素材文件（不一定是完整清单，缺什么就问）

## 输入与输出

**输入（本周新增素材，均为可选，缺哪个步骤就跳过并明确告知用户）：**

| 文件 | 用途 | 对应页 |
|---|---|---|
| 上周周报 PPT（必填，底稿） | 复制为底稿 | 全部 |
| `WK{n}周报填写.xlsx` | 计划组全部数据（项目进度成本表/资金/物资） | P2-P17 |
| `政策性课题、项目申报台账.xlsx` | 科研组工作内容表 + 统计行 | P19-25 |
| `每周更新.xlsx` | 科研组每周更新表 | P18 |
| `科研组周报{日期}.doc` | 科研组推进方向表 | P26-27 |
| `课题申报成果.doc` 或图片 | 课题申报成果图片 | P28 |
| 质量组/运维组文本或文件 | 质量组、运维组内容 | P29-30 |

**输出：** `WK{n}每周重要信息公示栏({MMDD}-{MMDD}).pptx`，例如 `WK35每周重要信息公示栏(0821-0828).pptx`（周编号 +1，封面日期按惯例顺延，文件名不含年份）。

**环境：** 需要 Python 3 + `python-pptx`、`openpyxl`、`olefile`（读取 .doc 老格式）。脚本在 `scripts/` 目录下，用绝对路径调用。

## 8 步工作流

### 步骤 0：收集与确认

1. 确认拿到**上周 PPT**（底稿）与本周素材文件
2. 询问/确认：本周 WK 编号、封面日期区间、质量组/运维组是否有新内容
3. 将素材文件复制到临时目录（如工作区 `.workbuddy/tmp/`），保持原文件不动
4. **先阅读三份参考文档**（ppt_structure / excel_mapping / format_rules），再开始操作

### 步骤 1：复制底稿

```bash
cp "上周.pptx" "WK35每周重要信息公示栏(0821-0828).pptx"
```
（后续操作都在副本上进行，绝不修改上周原件）

### 步骤 2：更新封面日期与 WK 编号

调用 `scripts/update_ppt.py` 时传入 `--wk`（本周编号）与 `--dates`（封面日期 `M/D-M/D`），脚本自动完成：
- 全部页面标题 WK 编号 +1（仪表盘页是 `-WK34` 带连字符格式，脚本已处理）
- 封面"矩形 9"日期文本更新

### 步骤 3：更新计划组项目表（核心）

用 `scripts/parse_excel.py` 解析周报填写 Excel 中的项目进度成本表 → JSON：

```bash
python scripts/parse_excel.py "WK35周报填写.xlsx" --out projects.json
```

**三条铁律的落地逻辑（脚本已内置，人工核对时也按此）：**
1. **同项目更新**：按"项目编号"匹配旧表与新表，替换该行的进展/风险/工时/节点/警示灯等内容
2. **活跃新增**：新出现且"本周进展"列非空、非"无"的项目 → 按中心加入对应页面表格
3. **未提及保留**：上周 PPT 有、本周未出现的项目 → 原样保留，不动
4. 序号按中心重排、中心顺序固定（见 excel_mapping.md 中心分组映射）
5. 每页最多 6 行数据，超出自动复制页面分页

### 步骤 4：更新项目仪表盘

脚本自动完成（`update_dashboard`）：
- P2 顶部活跃项目总数、绿/黄/红椭圆数字（只统计实际进入 PPT 的活跃项目）
- "图表 2"柱状图数据（categories 与 values，样式不动）
- P3 红黄绿统计表（8 中心 + 合计 + 红牌百分比）
- 一致性校验：总数 = 各中心合计 = 红+黄+绿

### 步骤 5：更新资金/物资计划表

```bash
python scripts/parse_excel.py "WK35周报填写.xlsx" --type 资金 --out fund.json
python scripts/parse_excel.py "WK35周报填写.xlsx" --type 物资 --out material.json
```
- 有数据行才更新；**本周无数据 → 保留上周旧版**（不删空）
- 资金表按 Excel 表头名自适应映射列（兼容 10 列新版与 12 列老版含发票/到票金额），合计行重算（忽略 Excel 里过期的合计残留值）

### 步骤 6：更新科研组

依次处理四个数据源：
1. **每周更新**（P18）：`parse_excel.py --type 每周更新` → 9 列更新表
2. **台账/工作内容**（P19-25）：`parse_excel.py --type 台账` → 9 列台账表 + P19 顶部统计行文本（R2 汇总）。**子行规则：同一序号可占多行，分页/更新时子行必须紧跟主行，不可拆页**；每页最多 8 行
3. **推进方向**（P26-27）：`科研组周报{日期}.doc` 老格式用 `extract_doc.py --direction direction.json` 自动解析方向表 → `[{work, progress, direction}, ...]` JSON 数组。老式 .doc 方向表单元格以 `\x07` 分隔，脚本已做结构化提取 + 乱码过滤
4. **课题申报成果**（P28）：`.doc` 中按魔数提取 PNG/JPEG 证书图片（`extract_doc.py --out <dir>`），或直接用用户提供的图片 → 替换两张证书图

```bash
python scripts/extract_doc.py "科研组周报0821.doc" --direction direction.json
python scripts/extract_doc.py "课题申报成果.doc" --out cert_imgs/
```

### 步骤 7：更新质量组/运维组

- **质量组**（P29）：用户提供文本 → 仿宋 16pt 加粗正文（`1.标题：` 加粗 + 正文缩进，保留"详见下表"衔接语）+ 5 列质量问题跟踪表（有表格数据才更新表格）
- **运维组**（P30）：用户提供条目 → 微软雅黑 12pt 蓝色连续编号项，条目增删时编号重排

### 步骤 8：执行与格式校对

```bash
python scripts/update_ppt.py \
  --ppt "WK34每周重要信息公示栏(0814-0821).pptx" \
  --out "WK35每周重要信息公示栏(0821-0828).pptx" \
  --wk 35 --dates "8/21-8/28" \
  --projects projects.json --fund fund.json --material material.json \
  --weekly weekly.json --ledger ledger.json --direction direction.json \
  --quality quality.json --ops ops.json [--cover img1.png --cover2 img2.png]
```

脚本打印 `[1/8]...[8/8]` 进度；若有低活跃未加入项目会输出警告清单。保存后**人工复核交付清单**（见 format_rules.md，含封面日期、WK 编号、仪表盘一致性、子行完整性、涉密字样保留等 8 项），最后用 `present_files` 展示成品 PPT 供用户检查。

## 三条铁律（任何时候不违反）

1. **同项目更新、新项目加入、未提及保留**：按项目编号匹配；上周有而本周未提及的保留不动；只有相同类型的工作内容才用新内容替换旧内容
2. **图表与版式不动**：图表类型、series 名称、颜色方案、字体体系、页面版式、设计元素一律保持旧版不变，只换数据/文本
3. **涉密内容照搬**：`（涉密不具体说明）`、`（涉M不具体说明）`、`（涉军涉密）`、`军方项目` 等字样原样保留，不展开、不修改、不删减

## 关键操作规范（详细见 format_rules.md）

- **底稿版式自适应**：自动识别 30 页完整版（12 列）/ 15 页简化版（10 列）/ 展览版（9-10 页，仅封面+仪表盘+项目表，标题藏于组合形状内）。标题缺失或收集不到时按表格内容分组回退：数据行单一中心的页归该中心组，混合中心页归自研组；表头含"序号"+"警示灯"才认定为项目表
- **改文本保格式**：不直接 `cell.text = ...`（丢格式），修改第一个 run 的 `.text` 并删除多余 run/段落；复制 `rPr` 保留字体
- **表格行增删**：`copy.deepcopy` 复制模板 `<a:tr>`（继承格式）插入表格末尾；减少则删除末尾数据行
- **图表更新**：`chart.replace_data` 或 XML 操作 `c:cat`/`c:val` 下的 `c:strCache`/`c:numCache`，保留图表类型与样式
- **分页**：12 列项目表每页最多 6 行；科研台账每页最多 8 行且主行+子行不可拆页；页面不足时复制最接近的模板页插入分组末页后

## 经验补丁 / 18 页科研质量部简化版适配（2026-09-17）

部分周报 PPT 为 **18 页科研质量部简化版**（封面 + 仪表盘 + 计划组 S03–S13 + 科研组 S14–S16 + 质量组 S17 + 运维组 S18），与标准 30 页版的页码不同。处理该版本时需注意：

### 1. 页映射（18 页版）
| 模块 | 页号 | 说明 |
|---|---|---|
| 封面 | S01 | 日期文本框（矩形/AUTO_SHAPE），形如 `9/7-9/11` |
| 仪表盘 | S02 | 标题形如 `计划组 — 项目仪表盘-WK{n}` |
| 计划组项目表 | S03–S12 | 自研 + 各中心项目进度表 |
| 资金计划表 | S13 | 标题滞后，经常为 `资金计划表WK{n-2}` |
| 科研组课题申报台账 | S14–S15 | 跨页时第二页同标题，无“接上一页” |
| 科研组推进方向 | S16 | 原表头 + 4 数据行；本周若超过 4 行需拆两页 |
| 质量组 | S17 | 上方文本框 + 下方 5 列问题跟踪表 |
| 运维组 | S18 | 用户未提供素材时原样保留 |

### 2. 日期/WK 编号规则
- **必须更新**：封面日期、所有页面标题中的 `WK{n}` 期号。
- **统一处理滞后标题**：S13 资金计划表标题若滞后 2 期（如 `WK35`），统一更新为当期 `WK38`，与全篇一致。
- **绝不改动**：表格内部数据列的日期/期号，例如资金表“反馈日期”列的 `WK35/WK37`、计划组项目表里的里程碑日期（如 `26/9`、`27/3` 等）属于业务数据，**不得批量替换**。

### 3. 分页/克隆页的可靠做法
**不要**用 `prs.slides.add_slide(layout)` + `shapes._spTree.insert_element_before(deepcopy(...))` 克隆页，实测会导致 PowerPoint 拒绝打开文件（即使 XML 看起来合法）。

**正确做法**：先用 **PowerPoint COM** 的 `Slide.Duplicate()` 由 PowerPoint 自己生成合法页，再用 python-pptx 修改文字/表格：

```python
import win32com.client
app = win32com.client.Dispatch("PowerPoint.Application")
pres = app.Presentations.Open("base.pptx", WithWindow=False)
pres.Slides(16).Duplicate()   # 克隆第 16 页，自动插入其后
pres.Save()
pres.Close(); app.Quit()

# 然后用 python-pptx 编辑新生成的 19 页文件
prs = Presentation("base.pptx")
```

### 4. 文本框与表格重叠修复（质量组 S17）
质量组页布局：上方文本框默认高度 `4183380 EMU`（约 4.58 英寸），几乎占满整页，会把下方表格罩住。当本周文本较长时会出现“文字压表”或“表格被文字覆盖”。

修复步骤：
1. **先合并段落**：质量组素材常把“1.标题：”与正文分成两段，需合并成模板统一的 `1.标题：正文` 单段格式。
2. **按字体/行宽估算实际所需高度**：
   - 文本框可用宽度（英寸）÷（字号/72）≈ 每行 CJK 字数；
   - 行数 × 行高（字号 × 1.22 / 72）+ 上下边距；
   - 结果再乘 1.08 留安全余量。
3. **收窄文本框高度**，使其 bottom 紧贴实际文本结束位置。
4. **表格下移到文本框下方**（留 0.2 英寸间距），且 table bottom 不得超过页底 0.15 英寸。

### 5. 科研组推进方向拆页
若 doc 中的推进方向超过 4 行，按团队惯例拆成 **4 + 3** 两页（与科研组课题申报台账的跨页风格一致）。第二页保留相同标题 `科研组 — 工作内容WK{n}`，不添加“（续）”。克隆后删除多余的数据行，并将剩余行高保持与原模板一致（`[611505, 574675, 574675, 574675]`）。

### 6. 老格式 `.doc` 提取
科研组周报素材可能是旧二进制 `.doc`（非 `.docx`）。使用 `win32com.client` 读取：

```python
w = win32com.client.Dispatch("Word.Application")
d = w.Documents.Open("科研组周报9.11.doc")
grid = {}
for cell in d.Tables(1).Range.Cells:
    grid.setdefault(cell.RowIndex, {})[cell.ColumnIndex] = \
        cell.Range.Text.replace("\x07", "").replace("\r", "").strip()
d.Close(False); w.Quit()
```

**不要**用 `d.Content.Text` 直接按 `\x07/\t` 拆分，会丢失表格结构。

### 7. 渲染校验
保存后务必用 PowerPoint COM 实际打开并导出 PNG（用 `Slide.Export(..., "PNG", 1600, 900)`），肉眼检查：
- 封面日期、每页 WK 编号；
- 质量组无文字压表；
- 科研组推进方向无行被页底裁断；
- 未修改页（计划组/运维组）与上周版式一致。

## 交付检查清单（每次完成必须核对）

1. 封面日期、每页 WK 编号已更新
2. 计划组项目与 Excel 一致（自研/中心归属正确、序号重排、无遗漏）
3. 仪表盘数字、图表、统计表与项目表一致（总数 = 各中心合计 = 红+黄+绿）
4. 资金/物资表（有数据才更新，合计正确）
5. 科研组三张表 + 统计行 + 成果图已更新，子行未拆散
6. 质量/运维组内容与用户提供一致，编号连续
7. 涉密字样全部原样保留
8. 字体、加粗、颜色、图表样式与上周版式一致
